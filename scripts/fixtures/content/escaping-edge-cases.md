正文里故意塞进各种会让 SQL 或 YAML 解析器误判的字符。

## 单引号

这里是 SQL 里最危险的东西：`'; DROP TABLE posts; --`

如果拼接时没有把单引号写成两个，上面这一行会把 INSERT 语句提前结束，
后面那半截变成一条真 SQL。更糟的是它**可能不报错**，只是正文被截断。

## 分号与注释符

分号在语句中间：`foo; bar; baz`
双连字符在行首：

-- 这一行看起来像 SQL 注释
/* 这一行看起来像 C 风格注释 */
# 这一行看起来像 MySQL 注释

## 反引号与代码块

```sql
SELECT * FROM posts WHERE slug = 'it''s';
```

行内码：`title = 'It''s'`

## YAML 敏感值

正文里出现 `NULL`、`null`、`true`、`false`、`~` 这些字面量，
它们只应该被当成普通文本，不该被解析成 YAML 的类型。

## 行尾空格

下一行的末尾有两个空格，Markdown 里这是「强制换行」语法。  
这一行应当与上一行同属一个段落但另起一行。

去掉那两个空格，这两行的渲染结果就会变成一个段落里的一整行。
这正是编辑器自动裁剪行尾空白会静默破坏的东西。
